# Audio-Feedback Sound Redesign — Design Spec

**Date:** 2026-07-15
**Plugin:** `plugins/audio-feedback`
**Status:** Design approved; ready for implementation plan.

## Problem

The audio-feedback plugin plays short synth sounds on Claude Code hook events.
Three things are wrong or missing:

1. **Incoherent event → sound mapping.** The lifecycle→pitch-contour logic is
   sound (rising = start/attention, falling = done/settle), but the tool-category
   dimension is mush: all `pre-*`/`post-*` category variants are near-identical
   0.53–0.62 s ticks with no systematic timbre rule.
2. **The generator recipe is lost.** The 8 event tones were authored via a web
   UI / one-off commands that were never committed. Git preserves the *note-map*
   (notes, contour, duration per sound) and the README character notes, but not
   the synthesis recipe. Confirmed unrecoverable: 0 `sox synth` lines in global
   bash history, no surviving session transcript, only a prose summary in memory.
   Only the **click engine** recipe survives (in `scripts/lib.sh`).
3. **Sounds are not premium.** Thin/gritty relative to Apple/Stripe-tier UI audio.

## Goals

- A **coherent sound family** with an intuitive, systematic event → sound mapping.
- A **committed, re-renderable generator** so recipes are never lost again.
- **Premium** sound quality.
- A **revamped token-driven click engine.**

Non-goal: changing the hook wiring, config keys, or theme system mechanics
(`sounds/<theme>/`). Those stay as-is.

## Decisions

- **Authoring tool: REAPER.** Mae designs the event tones visually in REAPER
  (she knows it; SWS + Python ReaScript installed at `~/.local/opt/REAPER/reaper`).
  Reproducibility comes from committing the REAPER project (`.rpp`, text) plus the
  rendered WAVs. The generator is *machine-bound* (needs REAPER + the same
  plugins) — accepted, because end users never generate sounds; they play shipped
  WAVs. The generator only ever runs on Mae's machine.
- **Rebuild mode: straight to upgraded.** Do not first reproduce today's sounds
  exactly. Go directly to the new premium + hybrid-category palette as the default.
  (The reconstruction work already done — see below — proves faithful recovery is
  possible and informs the targets, but is not itself shipped.)
- **Click engine stays sox.** The click sequence must synthesize *live inside the
  hook* at runtime — no DAW available there. It is retuned per premium principles
  but remains a sox recipe in `lib.sh`.

## Sonic system — hybrid (contour + accent)

The coherence backbone. Two orthogonal axes:

- **Pitch contour = lifecycle.** Direction encodes where in the lifecycle an event
  sits. Rising = starting / attention (`session-start`, `notification`,
  `pre-tool-use`). Falling to a resolved root = finished / settle (`stop`,
  `post-tool-use`, `subagent-stop`). This axis already exists in the originals and
  is kept.
- **Category = accent overlay.** Tool category is a short accent layered on the
  per-lifecycle base tone. Composable: new categories add new accents without
  touching the bases.

| Category   | Accent (starting point) |
|------------|-------------------------|
| execute    | tiny bright click       |
| network    | soft filtered whoosh    |
| modify     | short pluck             |
| observe    | soft tick               |
| dispatch   | double tick             |
| interact   | mid tick                |

Base tone tells you *where in the lifecycle*; accent tells you *what kind of tool*.
Exact accent timbres are a REAPER design-time decision, guided by these targets.

## Premium upgrade layer

Applied to every sound (from researched UI-audio best practice — see Sources):

- Soft attack shaping (no raw oscillator onset); always fade the tail to silence.
- Percussive/struck bodies with smooth exponential decay; avoid flat sustain.
- Inharmonic/bell-like partials over bare sines for "glassy" richness.
- Consonant intervals (unison + fifth + octave), kept within ~one octave (C4–C5).
- EQ: cut low-mid mud ~300–500 Hz; gentle high-shelf "air" ~6–10 kHz; tame the
  2.5–4 kHz fatigue zone / fizz.
- Reverb with 5–15 ms pre-delay, reverberance kept low; small bright space.
- Loudness: normalize the whole palette to one consistent target with ~1 dB
  headroom (−1 dBTP ceiling). No sound startlingly louder than another.
- Restraint: short, quiet, unobtrusive.

REAPER realizes these with a per-track FX chain (EQ → reverb → limiter to −1 dBTP)
and consistent render normalization, which is materially better than sox's synth
+ peak-normalize.

## Per-sound targets

The 8 base event tones, with measured characteristics from the current sounds as
*reference* (contour/notes to preserve) plus the premium targets above. Category
variants are generated by layering the accent overlay on the matching base.

| Sound | Contour / notes | Reference envelope |
|-------|-----------------|--------------------|
| `stop` | C4+G4 held fifth (C4 dominant, G4 ~−7 dB), settling | slow attack ~190 ms, decay ~710 ms |
| `notification` | A4 then C5 enters ~120 ms, C5 dominant (A4 ~−15 dB), ascending | attack ~290 ms, short decay ~200 ms |
| `session-start` | ascending C4–E4–G4 arpeggio, welcoming | ~0.94 s |
| `subagent-stop` | soft double ping E5 | ~0.66 s |
| `pre-compact` | low G3 tone, warning | ~1.1 s |
| `user-prompt-submit` | tiny high tick | ~0.55 s |
| `pre-tool-use` | short rising tick (base for pre-* accents) | ~0.53 s |
| `post-tool-use` | short falling tick (base for post-* accents) | ~0.54 s |

Targets are guidance for REAPER design, not exact reproductions (rebuild mode =
straight to upgraded). Note relationships and lifecycle contour must be preserved;
timbre and polish are upgraded.

## Architecture / deliverables

- **`sounds/src/audio-feedback.rpp`** — committed REAPER project, source-of-truth.
  One track + render region per event sound; synth + premium FX chain per track;
  render regions named to match hook-event WAV filenames.
- **`scripts/render-sounds.py`** (ReaScript) — batch-renders all regions to
  `sounds/default/*.wav` (mono, 44.1 kHz, consistent normalization). Documented
  invocation via the REAPER binary.
- **`sounds/default/*.wav`** — regenerated palette (committed).
- **`scripts/analyze.py`** — committed verification tool. FFT + envelope diff of a
  render against target (dominant partials, relative levels, attack, decay,
  loudness). Used to confirm renders hit spec and the palette is loudness-consistent.
- **Click engine** — retune the surviving sox recipe in `scripts/lib.sh` per the
  premium principles + existing token-driven rate curve. Stays sox.
- **Docs** — update `README.md` (sound table, category-accent explanation, REAPER
  regeneration workflow) and `CHANGELOG.md`; version bump.

## Work already done (informs, not shipped)

Reconstruction experiments in the session scratchpad validated the recovery method
and produced the reference targets above:

- `demo-sounds.sh` — A/B/C/hybrid audition of the four sonic-mapping approaches.
- `reconstruct.sh` — spectral-matched rebuild of `stop` + `notification` (matched
  the originals to <1 Hz partials, <1 dB levels, ~30 ms attack).
- `analyze.py` — the objective FFT/envelope diff tool (to be committed).

## Verification

- Each rendered sound passes `analyze.py` against its target (intended interval,
  envelope in range, no clipping).
- Palette loudness is consistent (no outlier LUFS/peak) with −1 dBTP headroom.
- The full theme regenerates from the committed `.rpp` via `render-sounds.py`.
- Manual audition: sounds map intuitively (lifecycle by contour, category by
  accent) and read as premium.
